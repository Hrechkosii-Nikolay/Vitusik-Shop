# Архітектура

Browser → REST API → SQLite (WAL, foreign keys, BEGIN IMMEDIATE).

Frontend у public/, GitHub Pages копія в docs/. API та domain/store окремо у server/. Schema включає users/customers/employees/roles, products/categories/brands/images/promotions, suppliers/receipts/lots/movements/stock view, orders/items/allocations/status history/payments/deliveries/POS sales/returns, favorites/reviews/notifications/audit.

Гроші зберігаються цілими копійками. Продаж фіксує закупівельну та продажну ціну. Одна транзакція об’єднує замовлення, FEFO-списання, знімки позицій, розподіл партій, платіж і статус. Якщо одна позиція не може бути продана, всі зміни відкочуються. Повторний запит повернення перевіряє вже повернену кількість. Скасування відновлює тільки невідновлені розподіли.

Наявність для покупця враховує лише непрострочені партії. У списання можна включати прострочені партії. FEFO на сервері автоматично розподіляє партії; продавець повинен фізично обрати відповідну одиницю за підказкою POS. Статуси — спрямований граф, термінальні статуси не відкриваються повторно.

SMS outbox у транзакції «Зібрано» унікальний за order/channel. Інтеграції зареєстровані контрактами в integrations.mjs. До вибору провайдера немає надсилання та списання коштів. Для реального провайдера підключити адаптер, серверний worker виклику drainNotifications, тест доставлення та retry/backoff. API Нової пошти підготовлено як серверний адаптер; UI наразі ручний.

Фінанси перевіряються сервером і відсутні в payload для продавця/адміністратора без прав. Обране й кабінет зберігаються у БД. Паролі — scrypt + випадкова сіль, сесійні й reset-токени — SHA256 у БД, оригінал session token тільки в HttpOnly cookie. Reset email черга з оригінальним посиланням потребує захисту диска й інтеграції пошти; адміністратор не бачить його в notifications API.

Подальший розвиток: інтерфейс repository для PostgreSQL, окремі migrations, multiwarehouse location_id, персональні дозволи продавців, idempotency key на створення онлайн-замовлень, WebSocket/SSE для миттєвого оновлення вітрини, серверна пагінація каталогу в UI, розгорнутий імпорт CSV і завантаження фото, інтеграції ПРРО/лояльності. Наразі UI завантажує до 2000 товарів, API підтримує limit/offset, q/category/brand.
